# Self-critique

## What it is

Attack each idea against an explicit rubric, then repair one structural element. Keep the original when the critique is generic.

## Mechanism

Self-Refine generates an initial output, asks the same model for feedback, and refines with that feedback. The paper reports that specific, actionable feedback drives the gain, while generic feedback or no feedback produces much smaller gains or none.

The counter-evidence matters. Huang et al. (2024) test intrinsic self-correction on reasoning tasks without external feedback. They find that models struggle to correct their own reasoning and often make answers worse. On GSM8K, GPT-3.5 kept its initial answer 74.7% of the time; when it changed, it was more likely to change a correct answer to an incorrect one. Multi-agent debate performed no better than self-consistency when compared at an equal number of responses.

The plugin uses the first finding and avoids the second failure mode. The critique is about a design, against four explicit criteria, not about a chain of reasoning. If the critique cannot name a concrete defect, the original stands.

## Experimental setup: Self-Refine

| Item | Value |
|---|---|
| Tasks | 7: code optimization, code readability, sentiment reversal, dialogue response, acronym generation, constrained generation, math reasoning |
| Models | GPT-3.5, ChatGPT, GPT-4; Codex for code tasks |
| Feedback | Task-specific, generated by the same model |
| Refinement | Same model, iterative |
| Metrics | Task metrics, automatic preference, human A/B |
| Human evaluation | 150 examples per dataset for A/B tasks; judges blind to method |

## Exact numbers: Self-Refine

- About 20% absolute average improvement across the seven tasks, as reported in the introduction.
- GPT-4 code optimization: 27.3% → 36.0%, +8.7 absolute.
- Dialogue response preference: 25.4% → 74.6%, +49.2.
- Math reasoning gains were modest. The paper attributes this to the difficulty of identifying a specific error in a math chain; ChatGPT's feedback was "everything looks good" for 94% of instances.
- Feedback quality ablation (ChatGPT on code optimization and sentiment reversal, GPT-3.5 on acronyms):

| Task | Specific feedback | Generic feedback | No feedback |
|---|---|---|---|
| Code optimization | 27.5 | 26.0 | 24.8 |
| Sentiment reversal | 43.2 | 31.2 | 0 |
| Acronym generation | 56.4 | 54.0 | 48.0 |

- Iteration gains: code optimization 22.0 → 28.8 over three iterations; sentiment reversal 33.9 → 36.8; constrained generation 29.0 → 49.7. Gains diminish with more iterations.
- Self-Refine with an external signal that identifies an incorrect math answer gains more than 5%.

## Exact numbers: the counter-evidence

From Huang et al. (2024):

- Intrinsic self-correction reduced accuracy on all tested benchmarks and models.
- GSM8K, GPT-3.5: 74.7% of the time the model retained its initial answer; changes were more likely to turn a correct answer into an incorrect one.
- Multi-agent debate was only slightly better than self-consistency with the same number of agents, and significantly worse than self-consistency with an equal number of responses.
- The improvements reported by some earlier self-correction work came from oracle labels or from a sub-optimal initial prompt. When the feedback is folded into the initial instruction, the gain disappears.

## Known limitations and conflicting results

- Self-Refine's gains are task-dependent. Preference-style tasks gain a lot; math reasoning gains little without an external checker.
- The feedback can be generic. Generic feedback produces a much smaller gain, and in some tasks none.
- The model can rationalize a bad idea. A critique that says "this is innovative" is not a critique.
- The critique criteria are the plugin's design, not a validated rubric.
- The accuracy-side counter-evidence is about reasoning. The plugin's critique targets ideas, not proofs. That distinction limits the transfer, but it does not prove the idea critique works.

## Prompt wording that produced the best results

Self-Refine's structure is feedback, refine, repeat. The paper's exact prompts are in its appendix; the main text reports the structure and the feedback-quality ablation, not a single verbatim prompt for all tasks.

The plugin's rubric is in `skills/jarvis-critique/SKILL.md`:

```
Attack the idea below, not the person who wrote it. Use four headings:
Novelty, Evidence, Feasibility, Specificity. For each, name one concrete
defect. Then repair the idea by changing exactly one structural element:
audience, mechanism, constraint, business model, or interface. If the repair
is cosmetic, say "kill" and stop.
```

This is an engineering construct. No paper tests this exact prompt.

## Design consequence

The pipeline critiques ideas, not reasoning chains. It requires a concrete defect. It keeps the original if the critique is generic. It allows "evidence gap" as a verdict instead of forcing a kill when the only problem is missing evidence.
